## 第一部分：Game Bible v0.1（原文整理）

**项目代号**：Blind Box Incremental Roguelite（暂定）
**创建日期**：2026-07-19

### 一、项目愿景（Vision）

目标不是做一个普通的盲盒游戏，也不是 Labubu 模拟器，而是：

> 打造一个原创潮玩 IP，并通过一款以盲盒为核心玩法的 Incremental Roguelite 游戏，让玩家不断收集、成长、自动化，最终形成可以长期运营的品牌。

游戏只是整个 IP 的第一款产品。未来可扩展：Steam DLC、新系列角色、实体周边、3D 打印、收藏册、动画、更多游戏。整个 IP 围绕同一套原创角色持续发展。

### 二、核心设计原则（Core Principles）

| # | 原则 | 说明 |
|---|------|------|
| 1 | **盲盒永远是核心玩法** | 所有系统必须服务于"让我再开一盒"。不是养成游戏、农场游戏、模拟经营——那些只是辅助系统。 |
| 2 | **参考 Scritchy Scratchy 的核心循环** | 学习：游戏循环、风险设计、自动化、Prestige、Incremental。不复制：刮刮卡、图案、规则、美术。借鉴机制，而不是内容。 |
| 3 | **功能准入标准** | 每个新功能必须回答："这个功能是否能让玩家更想继续开盲盒？"如果不能——删除。 |
| 4 | **围绕原创 IP** | 绝不使用 Labubu、Pop Mart 或任何已有角色。建立自己的收藏宇宙。 |

### 三、游戏定位

- 类型：Incremental / Roguelite / Blind Box Collection / Automation
- 一句话：**Earn coins. Crack blind boxes. Build your collection. Automate your toy empire.**

### 四、核心循环（Core Loop）

```
获得金币 → 购买盲盒 → 手动拆盲盒 → 获得奖励/风险
    → 收藏/出售/合成/分解 → 升级 → 自动化 → Prestige
    → 重新开始 → 更快成长
```

### 五、经济循环

金币来源三类，最终全部流向"购买盲盒"：

1. **稳定收入**：养成已拥有的角色，角色自动赚钱，玩家偶尔互动即可。
2. **主动收入**：小游戏（打包、分类、小任务）。作用是破产后快速恢复，不是主要收入来源。
3. **随机收入**：活动、任务、事件、隐藏奖励。

### 六、盲盒系统

- 盲盒是整个游戏的真正高潮。玩家的核心情绪是**期待**（"下一盒是什么？"），不是赚钱。
- **不同盒子拥有不同规则，不是只有不同概率。** 初步类型：普通盒、收藏盒、限定盒、神秘盒、工厂盒……后续继续设计。
- 拆盒必须有仪式感：拆包装 → 打开盒子 → 露出部分角色 → 最终揭晓。玩家应该享受揭晓过程本身。

### 七、奖励系统

盲盒可获得：普通角色 / 稀有角色 / 隐藏角色 / 特殊配件 / 金币 / 特殊事件 / 负面事件。

**重复角色绝不能毫无价值**，必须拥有出售、升级、合成、分解、收藏等用途。

### 八、自动化

玩家身份成长：收藏者 → 经营者 → 老板。

自动化包括：自动购买、自动拆盒、自动分类、自动出售、自动整理。玩家最终经营的是一条**流水线**。

### 九、Prestige

收益进入瓶颈后，进行：收藏展 / 赛季结算 / 品牌升级 → 获得永久成长。下一轮：更快、更多系统、更多系列。

### 十、原创 IP

- 统一美术风格；角色需高辨识度、可收藏、适合实体化、可持续扩展。
- 第一版目标约 40 个角色（**注：评审建议 Demo 阶段缩减，见第二部分**）。
- 整个 IP 是未来所有产品的核心资产。

### 十一、商业目标

- 短期：完成 Steam Demo
- 中期：正式上线 Steam
- 长期：打造原创潮玩品牌（实体盲盒、毛绒、钥匙扣、PVC 手办、3D 打印模型、更多游戏）

### 十二、团队分工

### 十三、协作方式

```
ChatGPT 讨论并制定设计 → 整理为正式需求 → Claude 实现 → Alex 试玩 → 反馈 → 继续迭代
```

**所有设计最终同步至 Game Bible，而不是依赖聊天记录。**

### 十四、Roadmap（原始版本，评审建议调整见第二部分）

- **Phase 1**：完成 Game Bible、世界观、经济系统、第一版核心循环
- **Phase 2**：完成第一季原创角色设计（约 40 个）、统一美术规范
- **Phase 3**：Unity Prototype（开盒、收藏、经济、自动化、Prestige）
- **Phase 4**：Steam Demo，收集玩家反馈，调整核心循环

### 十五、北极星（North Star）

> 让玩家一直想说："我再开最后一盒就睡觉。"
>
> 如果某个功能不能增强这种体验，就不应该进入游戏。

## 第二部分：技术评审结论（Claude, 2026-07-18）

### 总体判断

**合理，可以做。** 增量类游戏是独立开发者最容易做完、最容易验证的品类之一；"盲盒开箱"作为核心动作有天然的期待感和仪式感；参考已验证的循环做机制迁移是成立的路线。

文档中最有价值的两条：
- 原则三（功能不服务"再开一盒"就删）
- "重复角色绝不能毫无价值"

这两条守住了，游戏就不会散架。

### 七个关键问题与建议

#### 1. 仓库与技术方案（已解决）

原本讨论所在的 `alexHuangWind/gallery` 仓库是 Flutter Gallery 的 fork，不适合承载 Unity 游戏工程。
**决议：新建独立的本地项目 + 全新 GitHub 仓库。** Unity 编辑器只能在本地运行，主开发环境必须在本地（详见第三部分）。

#### 2. "Roguelite" 目前名不副实 ⚠️ 待设计

当前循环是纯 Incremental + Prestige，缺少 roguelite 的"单局失败风险 + 带着永久成长重开"结构。参考对象 Scritchy Scratchy 的上头感恰恰来自风险机制（刮到炸弹会炸掉收益）——**风险设计是循环的心脏，不是配菜**。

**待 ChatGPT（Product Director）明确定义**：
- 盲盒里的"负面事件"具体是什么？
- 会不会导致一轮结束（失败状态）？
- 如果不做失败机制，就从定位中移除 roguelite 标签，做纯 incremental 也完全成立。

#### 3. Phase 顺序建议倒置 ⚠️ 重要

原 Roadmap 是"先做 40 个角色美术，再做原型"。风险：核心循环未验证前，美术投入可能全部作废。

**建议顺序**：
1. 先用占位美术（色块/emoji/免费素材）做**垂直切片**：8–10 个角色、1 种盒子、开盒动画、重复角色出售、一条升级线、一个自动化解锁。
2. 验证"想再开一盒"成立后，再启动第一季角色设计。
3. Demo 阶段 12–15 个角色（含 1–2 个隐藏款）足以撑起收集欲，40 个留给正式版。

#### 4. 3D 管线可能过重

Meshy 生成 + Blender 清理 40 个 3D 角色成本很高。增量类游戏用 2D 立绘/半 3D 渲染图完全够用，且 2D 更容易保持"高辨识度、适合实体化"的统一风格。**3D 留给确定做实体周边之后。**

#### 5. 缺数值表 ⚠️ 待交付

目前没有任何具体数字：盒子价格曲线、角色产出速率、稀有度概率、Prestige 收益倍率。必须先在表格里模拟跑通（多久遇到第一个瓶颈、一轮 Prestige 多长时间），否则原型大概率"要么太快无聊、要么太慢劝退"。

**这是 ChatGPT（Product Director）的下一份交付物。**

#### 6. 合规红线 🚨 写入 Bible

盲盒 + 游戏内货币 + 买断制 → 没有问题。
但如果加入**真钱购买随机盲盒** → 构成 loot box，在 Steam 及部分国家（比利时、荷兰等）触发合规问题。

**建议写死一条原则：真钱永远买不到随机性。**

#### 7. IP 愿景先收进抽屉

实体周边、动画、收藏册写在愿景里没问题，但短期内不应影响任何决策——**唯一例外**：角色设计时保持"轮廓清晰、配色简单、适合缩小"，这条现在就该进美术规范。

### 修订后的近期路线

```
① 确定引擎与仓库（→ 已定：本地 Unity 新项目）
② ChatGPT 交付：数值表 + 风险机制（roguelite）定义
③ Claude 搭建垂直切片（占位美术，8–10 角色，1 盒型）
④ Alex 试玩验证"再开一盒"手感 → 迭代
⑤ 循环成立后 → 启动第一季角色美术（12–15 个用于 Demo）
⑥ Steam Demo
```

## 第三部分：本地项目搭建指南

### 1. 目录与命名

```
/Users/changyu/Developer/Ai/ClaudeHome/SteamGames/BlindBoxRoguelite
```

### 2. 初始化步骤（在 Mac 终端执行）

```bash
mkdir -p /Users/changyu/Developer/Ai/ClaudeHome/SteamGames/BlindBoxRoguelite
cd /Users/changyu/Developer/Ai/ClaudeHome/SteamGames/BlindBoxRoguelite
git init
mkdir docs
# 将本文档放入 docs/ 目录
```

然后：
1. 在 GitHub 新建一个空仓库（如 `BlindBoxRoguelite`），关联为 remote。
2. 用 **Unity Hub** 在此目录创建 Unity 工程（建议 Unity 6 LTS，2D 或 URP 模板视美术方向而定）。
3. 添加 Unity 专用 `.gitignore`（排除 `Library/`、`Temp/`、`Logs/`、`obj/`、`UserSettings/` 等，可用 GitHub 官方 Unity gitignore 模板）。
4. 本地启动 Claude Code（CLI 在项目目录运行 `claude`，或用桌面应用打开该文件夹；未安装 CLI 先执行 `npm install -g @anthropic-ai/claude-code`）。

### 3. 建议的项目结构

```
BlindBoxRoguelite/
├── docs/
│   ├── GameBible.md          ← 唯一权威设计文档，持续更新
│   ├── Economy.md            ← 数值表/经济模型（待 ChatGPT 交付）
│   └── ArtGuide.md           ← 美术规范（第一季角色设计前完成）
├── Assets/                   ← Unity 工程
├── Packages/
├── ProjectSettings/
├── prototype/                ← （可选）网页版数值原型，验证循环手感
├── CLAUDE.md                 ← 本地 Claude Code 的项目说明
└── .gitignore
```
